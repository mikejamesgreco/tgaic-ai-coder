TGAIC AI Coder - Quick Command Reference
The Greco AI Coder
=========================================

Purpose
-------
This file is a command companion for the TGAIC README, Help, and References material.
It contains the common Windows commands used to install, start, stop, restart, and
troubleshoot the local TGAIC runtime.

TGAIC runtime path
------------------
TGAIC HTML
  -> PowerShell Bridge on 127.0.0.1:8787
  -> llama-server / llama.cpp on 127.0.0.1:8080
  -> local GGUF model cache under C:\Models


1. INSTALL LLAMA.CPP
====================

Install with winget:

winget install llama.cpp

If winget reports that PATH changed, close Command Prompt and open a new one.

Verify:

llama-server --version
where llama-server


2. STANDARD MODEL CACHE
=======================

In every new Command Prompt that will run llama.cpp, set:

set LLAMA_CACHE=C:\Models

This tells llama.cpp to use C:\Models as the managed model cache.


3. DOWNLOAD / CACHE A MODEL
===========================

Stop router mode first if it is currently running.

Example 1.5B model:

set LLAMA_CACHE=C:\Models
llama-server -hf Qwen/Qwen2.5-Coder-1.5B-Instruct-GGUF:Q4_K_M

Example 3B model:

set LLAMA_CACHE=C:\Models
llama-server -hf Qwen/Qwen2.5-Coder-3B-Instruct-GGUF:Q4_K_M

Wait for the model to download and load successfully.

When complete, press:

Ctrl+C

The model remains cached under C:\Models.


4. START LLAMA-SERVER IN TGAIC ROUTER MODE
==========================================

Normal TGAIC startup:

set LLAMA_CACHE=C:\Models
llama-server --host 127.0.0.1 --port 8080 -c 8192

Important:
- Router mode intentionally does NOT include -hf.
- Router mode intentionally does NOT include -m.
- Leave this Command Prompt window running while using TGAIC.


5. START THE TGAIC POWERSHELL BRIDGE
====================================

Open a second Command Prompt in the repository folder.

Run:

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tgaic-ai-coder-bridge-v0030.ps1

Expected bridge endpoint:

http://127.0.0.1:8787/

Expected upstream llama.cpp endpoint:

http://127.0.0.1:8080/v1

Leave this window running while using TGAIC.


6. OPEN TGAIC
=============

Download or clone the repository.

Then double-click:

tgaic-ai-coder.html

The supported runtime is the local file:// copy.

Default TGAIC endpoint:

http://127.0.0.1:8787/v1

Then use:
- Connect
- Refresh Models
- Load Selected


7. NORMAL STARTUP SEQUENCE
==========================

Window 1 - llama.cpp:

set LLAMA_CACHE=C:\Models

Window 2 - TGAIC bridge:

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tgaic-ai-coder-bridge-v0030.ps1

Browser:

Double-click tgaic-ai-coder.html


8. NORMAL SHUTDOWN SEQUENCE
===========================

Option A - from TGAIC:
- Use Stop Bridge to stop the PowerShell bridge.
- llama-server continues running separately.

Option B - from console windows:

Bridge console:
Ctrl+C

llama-server console:
Ctrl+C

Closing tgaic-ai-coder.html does not automatically stop either process.


9. RESTART THE BRIDGE
=====================

Stop the existing bridge:

Ctrl+C

Then start it again:

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tgaic-ai-coder-bridge-v0030.ps1


10. RESTART LLAMA-SERVER
========================

Stop llama-server:

Ctrl+C

Restart router mode:

set LLAMA_CACHE=C:\Models
llama-server --host 127.0.0.1 --port 8080 -c 8192

Then return to TGAIC and use:

Refresh Models

Load Selected


11. ADD ANOTHER MODEL LATER
===========================

Step 1 - stop router mode:

Ctrl+C

Step 2 - keep the TGAIC cache configured:

set LLAMA_CACHE=C:\Models

Step 3 - run the desired Hugging Face GGUF once:

llama-server -hf user/repository:quant

Example:

llama-server -hf Qwen/Qwen2.5-Coder-7B-Instruct-GGUF:Q4_K_M

Step 4 - wait for the model to download/load.

Step 5 - stop that temporary model session:

Ctrl+C

Step 6 - restart generic router mode:

set LLAMA_CACHE=C:\Models
llama-server --host 127.0.0.1 --port 8080 -c 8192

Step 7 - in TGAIC:

Refresh Models
Load Selected


12. RUN A LOCAL GGUF FILE DIRECTLY
==================================

If you already have a GGUF file:

llama-server -m "C:\Models\your-model.gguf" --host 127.0.0.1 --port 8080 -c 4096

Use this for direct/manual model startup rather than router mode.


13. OPTIONAL HUGGING FACE TOKEN
===============================

Set a Hugging Face token for the bridge process:

set HF_TOKEN=hf_your_token_here
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tgaic-ai-coder-bridge-v0030.ps1

Alternative:
Enter the token directly in the TGAIC HF Token field.

TGAIC does not persist the HTML-entered token.

17. COMMON PROBLEMS
===================

Problem:
'llama-server' is not recognized.

Try:
- Close the Command Prompt opened before installation.
- Open a new Command Prompt.
- Run:
  where llama-server
  llama-server --version


Problem:
TGAIC says the bridge is unavailable.

Check:
curl http://127.0.0.1:8787/health

Then confirm the bridge console is still running.


Problem:
Bridge is running but TGAIC cannot see the model.

Check:

curl http://127.0.0.1:8080/health
curl http://127.0.0.1:8080/v1/models

Then restart llama.cpp in router mode if necessary.


Problem:
Only one model appears after adding another model.

Restart generic router mode:

Ctrl+C

set LLAMA_CACHE=C:\Models
llama-server --host 127.0.0.1 --port 8080 -c 8192

Then use Refresh Models in TGAIC.


Problem:
Browser CORS errors.

Use the current TGAIC PowerShell bridge.
The browser UI should talk to:

http://127.0.0.1:8787/v1

not directly to llama-server.


Problem:
GitHub Pages copy cannot reach the bridge.

Download tgaic-ai-coder.html and run the local copy from disk.
The hosted HTTPS page may be blocked from calling the local HTTP bridge.

21. LOCAL RAG QUICK START
=========================

TGAIC v0033 + bridge v0030 include bridge-managed, token-aware local RAG.

Start llama-server in router mode:

set LLAMA_CACHE=C:\Models
llama-server --host 127.0.0.1 --port 8080 -c 8192

Start the bridge:

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tgaic-ai-coder-bridge-v0030.ps1

Open the downloaded local HTML, connect, and load the desired coding model.

Then:
  1. Expand "Local Knowledge / RAG".
  2. Click Add Files or Add Folder.
  3. Confirm the desired model is selected.
  4. Click Build / Rebuild Index.
  5. Leave "Enable RAG for chat" checked.
  6. Ask questions normally.

Default settings:
  Chunk target        800 tokens
  Chunk overlap       150 tokens
  RAG budget         4000 tokens/question
  Maximum chunks        8


22. WHAT RAG DOES
=================

RAG = Retrieval-Augmented Generation.

It does NOT retrain the GGUF model. It retrieves relevant reference chunks and
adds them temporarily to the prompt for the current question.

INDEXING:

local files
   |
   v
TGAIC browser
   |
   v
PowerShell bridge
   |
   +--> llama-server /tokenize using selected model
   |
   v
overlapping token-sized chunks
   |
   v
%LOCALAPPDATA%\TGAIC\rag-index.json

QUESTION:

question
   |
   v
bridge lexical/code-aware retrieval
   |
   v
best matching chunks within token budget
   |
   v
TGAIC prompt + filename/line provenance
   |
   v
coding model inference
   |
   v
grounded answer


23. TOKENIZATION VS EMBEDDINGS
==============================

TOKENIZATION
------------
Text -> discrete token IDs / token pieces.

TGAIC currently calls llama-server /tokenize using the selected model. This is
important because different model families can tokenize the same text
differently. Using the real tokenizer makes the 800-token chunk target,
150-token overlap, and 4000-token RAG budget meaningful to that model.

In llama-server router mode, /tokenize must receive the model name. TGAIC sends
the currently selected model automatically.

EMBEDDINGS
----------
Text -> semantic numerical vector.

Embedding RAG normally does this:

reference chunk -> embedding model -> vector
question        -> same embedding model -> query vector
vectors         -> similarity search -> nearest chunks -> coding model

Tokenization and embeddings are NOT the same thing.

Current TGAIC:
  model-aware tokenization + lexical/code-aware retrieval

Possible future TGAIC:
  lexical retrieval + embedding similarity + optional reranker

llama-server supports /v1/embeddings when an appropriate embedding model is
loaded. TGAIC does not currently build/store embedding vectors.


24. CURRENT RETRIEVAL METHOD
============================

The bridge currently performs lexical/code-aware retrieval. It favors useful
coding signals such as:
  - exact identifiers
  - class/package/procedure names
  - table/column names
  - filenames
  - repeated query terms
  - exact phrase/text matches

This is often effective for source-code RAG because engineering questions
frequently contain the exact names present in the source.

Retrieved chunks carry filename and approximate line-range provenance.


25. RERANKING / HYBRID RAG
==========================

A more advanced pipeline can retrieve candidates quickly and then use a
dedicated reranker model to reorder them:

question
   +--> lexical search ----+
   +--> embedding search --+--> candidates --> reranker --> coder model

llama-server exposes reranking support with an appropriate reranker model.
TGAIC does not currently use a reranker.


26. WHEN TO REBUILD THE RAG INDEX
=================================

REBUILD when:
  - a reference file changed
  - adding/removing reference files
  - chunk target or overlap changed
  - switching to a materially different model/tokenizer and you want exact
    model-specific chunk boundaries/token counts
  - intentionally replacing the knowledge set

NO REBUILD needed merely because:
  - the HTML page was closed/reopened
  - the bridge was restarted and successfully reloaded the persisted index

The bridge persists the index at:
  %LOCALAPPDATA%\TGAIC\rag-index.json

The UI shows:
  STAGED  = newly selected in the current browser session
  INDEXED = persisted in the bridge-managed RAG index


27. RAG CONTEXT BUDGET
======================

RAG evidence shares the model's finite context window with:
  - system instructions
  - conversation history
  - current user question
  - generated answer

A 4000-token RAG budget is a maximum, not a target. TGAIC can retrieve fewer
tokens/chunks when fewer are relevant.

If llama-server is started with:
  -c 8192

then 8192 is the configured runtime context size. Do not assume all 8192 tokens
are available for RAG alone.


28. LOCALITY / PRIVACY
======================

RAG reference files and the generated index remain local to the TGAIC workflow.
They are not sent to Hugging Face.

Hugging Face traffic is limited to explicit Model Browser activity.

Clear Index removes the bridge's persisted local RAG index.


29. RAG TROUBLESHOOTING
=======================

"model name is missing from the request"
  Router-mode llama-server needs a model identifier on /tokenize.
  Use TGAIC v0033 + bridge v0030 together and select/load a model first.

Persisted list empty after reopening
  Confirm bridge v0030 is running. The bridge returns an indexed-file manifest
  through /rag/status and TGAIC repopulates INDEXED references from it.

"undefined · 0 chunks · 0 indexed tok"
  This was caused by an older nested-array manifest response. Bridge v0030
  removes the extra wrapper and TGAIC v0033 defensively flattens the response.

RAG enabled but no chunks retrieved
  The current question did not score strongly enough against the lexical/code
  index. Try exact class, method, table, package, filename, or identifier names.


30. OFFICIAL LLAMA.CPP RAG-RELATED ENDPOINTS
===========================================

llama-server documentation:
https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md

Relevant capabilities:
  POST /tokenize
      Tokenizes text with the target model. Used by current TGAIC RAG.

  POST /v1/embeddings
      Produces embedding vectors with an embedding-capable model.
      Candidate for future semantic TGAIC RAG.

  POST /rerank  (aliases include /v1/rerank)
      Reranks candidate documents with a suitable reranker model.
      Candidate for future hybrid TGAIC RAG.
