Local setup — complete Windows installation and startup guide

Current companion bridge: tgaic-ai-coder-bridge-v0025.ps1. The HTML and bridge are separate files; use the current bridge when running this page.

Architecture. TGAIC is the HTML conversation UI. The PowerShell bridge listens on 127.0.0.1:8787 and provides the browser-safe API/CORS boundary. llama-server listens on 127.0.0.1:8080, loads the GGUF model, and performs inference. Keep both console windows open while chatting.

Communication path. Every chat request follows this local round trip. The HTML never talks directly to llama.cpp; the PowerShell bridge is the browser-facing boundary and forwards the OpenAI-compatible request to llama-server. The streamed response comes back through the same path.

The bridge does not generate answers and does not own the conversation. TGAIC keeps the chat history in the browser and sends the required messages with each request. llama-server owns model loading/inference. The bridge primarily provides the safe local HTTP/CORS boundary and streams traffic in both directions.

1. Install llama.cpp. Open Command Prompt and run:

winget install llama.cpp

Winget may report that PATH was modified. If so, close that Command Prompt and open a new one. Verify the installation:

llama-server --version
where llama-server

2. Start a model with llama-server. The easiest method is -hf, which lets llama.cpp obtain a compatible GGUF model from Hugging Face. Our known-working laptop example is:

llama-server -hf Qwen/Qwen2.5-Coder-1.5B-Instruct-GGUF:Q4_K_M --host 127.0.0.1 --port 8080 -c 4096

The first launch downloads/caches the model. Wait until the console reports model loaded and listening on http://127.0.0.1:8080. Leave this window running.

3. Alternative: run a GGUF file you already downloaded.

llama-server -m "C:\Models\your-model.gguf" --host 127.0.0.1 --port 8080 -c 4096

-hf is convenient for downloading/running a Hugging Face GGUF repository; -m is useful when you want explicit control over a local GGUF file.

4. Start the TGAIC PowerShell bridge. Put the bridge PS1 somewhere convenient, open a second Command Prompt in that directory, and run:

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tgaic-ai-coder-bridge-v0025.ps1

The bridge should report Listening : http://127.0.0.1:8787/ and Upstream : http://127.0.0.1:8080/v1. Leave this second console window running.

5. Open TGAIC. Double-click this HTML file. It is intentionally opened directly from disk as a file:// application. The endpoint should remain:

http://127.0.0.1:8787/v1

Leave the Model field blank and click Connect. TGAIC first checks the bridge and then requests /v1/models; the loaded llama.cpp model should be discovered automatically. A green Connected · 1 model badge means the entire chain is working.

6. Chat. Type a prompt and press Enter to send. Use Shift+Enter for a new line. Stop aborts the current generation. Disconnect disconnects the HTML UI but leaves the bridge and llama.cpp running. Stop Bridge asks the PowerShell bridge to exit; llama.cpp continues running separately.

7. Shut everything down. Use Stop Bridge or press Ctrl+C in the bridge console. Then press Ctrl+C in the llama-server console to unload the model and stop the inference server. Closing the HTML page does not automatically stop either process.

8. Start again later. You do not normally need to reinstall llama.cpp or redownload an already cached model. Start llama-server with the desired model, start the bridge, double-click TGAIC, and click Connect.

Useful checks.

llama-server --version

curl http://127.0.0.1:8080/health

curl http://127.0.0.1:8080/v1/models

curl http://127.0.0.1:8787/health

curl http://127.0.0.1:8787/v1/models

Troubleshooting. If TGAIC says the bridge is unavailable, confirm the PowerShell bridge is running on port 8787. If the bridge is ready but the model request fails, confirm llama-server is still running on port 8080. If llama-server is not recognized immediately after installation, open a new Command Prompt so the updated PATH is loaded. If the browser reports CORS errors, use the current TGAIC bridge; it owns the browser-facing CORS headers and deliberately does not pass conflicting llama.cpp CORS headers through.

Model notes. llama.cpp runs models in GGUF format. Hugging Face hosts many llama.cpp-compatible GGUF repositories. With -hf user/repository:quant, the quantization suffix selects a variant such as Q4_K_M. Smaller parameter counts and stronger quantization generally reduce memory requirements; larger models generally require more RAM/VRAM and take longer to generate. Hardware determines which model size is practical.

9. Standard TGAIC model-cache setup. We use llama.cpp's cache as the normal TGAIC model library and explicitly place it under C:\Models. In each new Command Prompt that will run llama.cpp, set:

set LLAMA_CACHE=C:\Models

This environment variable applies to that Command Prompt and processes launched from it. Models downloaded with -hf while it is set are cached under C:\Models and do not need to be downloaded again.

10. Download/add a model to the TGAIC cache. Stop router mode first with Ctrl+C, keep LLAMA_CACHE=C:\Models set, and launch the desired Hugging Face GGUF model once. Examples:

REM Known-working 1.5B baseline
llama-server -hf Qwen/Qwen2.5-Coder-1.5B-Instruct-GGUF:Q4_K_M

REM Better 3B model tested successfully on this laptop
llama-server -hf Qwen/Qwen2.5-Coder-3B-Instruct-GGUF:Q4_K_M

Wait for the download to reach 100% and for llama.cpp to report model loaded. The model is now cached. Press Ctrl+C; you do not need to use that -hf command again unless you deliberately remove the cached model.

11. Restart llama.cpp in TGAIC router mode. After adding models, return to the normal TGAIC server command:

set LLAMA_CACHE=C:\Models
llama-server --host 127.0.0.1 --port 8080 -c 8192

Notice that this command contains no -hf and no -m. That is intentional. llama.cpp is now acting as the model router instead of immediately loading one specific model. Start the bridge, open TGAIC, and click Refresh Models. The cached models should appear in the Local Model Manager and can be loaded from the page.

12. What we verified. We downloaded Qwen2.5-Coder 1.5B and 3B Q4_K_M models with LLAMA_CACHE=C:\Models, then confirmed both appear after restarting llama-server in generic router mode. We also successfully ran a roughly 3.4 GB / 6B-class GGUF on a machine with only 2 GB of GPU VRAM. That is an important practical result: a GGUF does not have to fit entirely in VRAM. llama.cpp can place some work on the GPU and use system RAM/CPU for the remainder. Performance still depends on the model, quantization, context size, total system RAM, memory bandwidth, and how much can be offloaded. The repeatable workflow remains: download/cache once → restart router → Refresh Models → Load Selected → chat.

13. Cache versus --models-dir. These are related but different. LLAMA_CACHE=C:\Models tells llama.cpp where its managed/downloaded cache lives. --models-dir "C:\SomeFolder" is useful when you already have manually managed GGUF files in a directory and want the router to discover them. For the normal TGAIC workflow, use LLAMA_CACHE=C:\Models. You can still add --models-dir later for a separate collection of manually downloaded GGUF files.

14. Where to find models online. There is no small fixed "full list" built into llama.cpp. Hugging Face is the primary catalog and contains a very large, changing collection of GGUF models. Use these references:

  • Hugging Face — all models filtered to the GGUF library ↗ — the broad catalog. Search within it for terms such as coder, Qwen, Gemma, or a parameter size.
  • Hugging Face — GGUF model search ↗ — another convenient browse/search view.
  • llama.cpp — Obtaining and quantizing models ↗ — official llama.cpp model documentation, including the -hf user/model[:quant] syntax.
  • Qwen2.5-Coder 3B Instruct GGUF ↗ — the 3B coder model now tested on this laptop.
  • Qwen2.5-Coder 7B Instruct GGUF ↗ — a substantially larger next step for stronger hardware.

15. Reading a Hugging Face GGUF model page. Prefer an Instruct or chat-tuned model for TGAIC rather than a base/pretraining model. Confirm that the repository contains GGUF files and is compatible with llama.cpp. Model repositories commonly provide multiple quantizations. Q4_K_M is a useful starting point because it balances model size and quality. Higher-bit quantizations such as Q5/Q6/Q8 generally require more memory/disk but preserve more model information.

16. Model size versus VRAM. Parameter count, GGUF file size, VRAM, and total system RAM are related but they are not the same limit. A model larger than available VRAM can still run because llama.cpp can split/offload work across GPU and CPU/system RAM. On the current 2 GB-VRAM test laptop, 1.5B and 3B models are proven, and a roughly 3.4 GB 6B-class coder/reasoning GGUF also runs acceptably. Treat the browser's file-size buckets as discovery aids rather than hard hardware limits. Larger models may load but become slower, consume more system RAM, or require a smaller context.

18. Important model-selection rule. Do not assume every model shown on Hugging Face is suitable merely because it contains a GGUF. Check parameter count, quantization/file size, model architecture/support, total RAM/VRAM, and whether the repository contains companion files. Some multimodal models use an mmproj companion; other repositories may include optional MTP/NextN-style sidecars. A download completing successfully does not prove that the exact GGUF conversion can be loaded by the installed llama.cpp build. TGAIC therefore treats compatibility as advisory and defaults the Hugging Face browser to Text GGUF only.

19. Hugging Face Model Browser. The online discovery panel searches GGUF repositories through the bridge. Enter a search such as coder, Qwen, or Gemma. Search criteria do not contact Hugging Face until you click Search Models. Page filling is handled by the bridge: it continues through Hub results until it has enough matching repositories for the requested TGAIC page or the Hub search is exhausted. Sort choices are only those supported by the Hugging Face model API, so sorting applies to the global Hub traversal rather than merely reordering one local page. The bridge also detects mmproj/MTP companion files and adds a compatibility hint. Use Copy -hf to copy the standard cache command plus the generated llama-server -hf user/repository:quant command. Downloading remains intentionally manual: stop router mode, paste/run the command, wait for the model to cache/load, stop that model with Ctrl+C, restart generic router mode, then use Refresh Models.

Current recommended routine: use the Hugging Face GGUF catalog to discover a model → copy its user/repository:quant identifier → set LLAMA_CACHE=C:\Models → run it once with llama-server -hf ... to download/cache it → Ctrl+C → restart the generic router → Refresh Models in TGAIC → Load Selected.

20. Hugging Face authentication, rate limits, and efficient search

Hugging Face allows anonymous API access, but larger or repeated searches can be rate limited. TGAIC supports optional authenticated requests in two ways.

Option A — HTML token field: enter an Hugging Face access token in the HF Token field in the model browser. The page sends it only to http://127.0.0.1:8787 in the X-HF-Token header. The bridge converts it to a Hugging Face Bearer token. TGAIC does not save this value to localStorage, sessionStorage, cookies, or a file; reloading or closing the page clears it.

Option B — environment variable:

set HF_TOKEN=hf_your_token_here
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tgaic-ai-coder-bridge-v0025.ps1

If both are present, the token entered in the HTML page takes precedence for that request. The bridge never prints the token itself.

API efficiency: the Hugging Face search response already includes model tags. The bridge first keeps only results tagged gguf (or clearly named as GGUF) and only then requests repository trees to discover exact GGUF filenames and sizes. This avoids a tree API call for every arbitrary model returned by the search.

Pagination: Results per page defaults to 10 and can be set from 1 to 100. A TGAIC page is result-oriented rather than tied one-for-one to a Hugging Face API page: the bridge follows as many Hub pages as necessary to collect the requested number of matching GGUF repositories, stopping early only when Hugging Face has no more results. The continuation cursor also remembers an offset within a Hub page so matches are not skipped between TGAIC pages.

21. Model compatibility and failed loads

A completed Hugging Face download and a valid .gguf filename are not a guarantee that the model will load. We encountered a Qwen3.5-derived GGUF that downloaded successfully but failed during llama.cpp tensor validation with a missing-tensor error. That type of failure happens after download and is distinct from cache/network problems.

TGAIC's compatibility column is therefore a pre-download hint, not a certification. It can identify obvious text versus multimodal repositories and companion files, and it can flag newer architecture families for extra caution, but the definitive compatibility test is still whether the installed llama.cpp build loads the exact GGUF conversion.

On Windows, llama.cpp may print failed to create symlink: A required privilege is not held by the client followed by switching to degraded mode. If the process continues afterward, that warning by itself is not the fatal model-load error; inspect the later llama.cpp messages for the actual failure.

22. Markdown responses

Assistant output is rendered as safe Markdown in the browser. Common headings, bold/italic text, numbered and bulleted lists, inline code, fenced code blocks, blockquotes, links, horizontal rules, and basic Markdown tables are supported. Fenced code blocks include a language label and Copy button. Model-produced HTML is escaped rather than trusted/executed.

23. Internet access and tool boundaries

The local GGUF model itself does not browse the web, scrape sites, or search the Internet. Current chat inference is local. The Hugging Face Model Browser is a specific bridge feature that performs Hub API requests only when you initiate a model search. General web search, arbitrary URL fetching, autonomous browsing, image generation, and reference-file/RAG tooling are not currently part of TGAIC.
